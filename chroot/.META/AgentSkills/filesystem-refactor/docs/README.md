# filesystem-refactor

引用感知的文件系统重构：让 Agent 在移动、重命名、合并、替换、删除文件和目录时，先探知冲突与引用，按声明的语义执行，再修复引用并验证结果。

## 它解决什么问题

普通的 `mv` 只搬文件，不管后果：

- **引用断裂**：代码里的 import、Markdown 里的链接、配置里的路径，原地不动，指向一个已不存在的位置；
- **语义漂移**：目标目录已存在时，`mv` 的默认行为可能是嵌套、合并或覆盖——和你说的"移动"不是一回事；
- **没有退路**：操作即生效，出错后现场已经变了。

`filesystem-refactor` 把这类操作变成一次完整的重构事务：上级 Agent 声明意图，worker 探知现场、确认引用、执行并验证；发现实际行为会偏离声明的语义时，打回报告，而不是替你猜测。

## 它的设计

- **上级 Agent** 是意图所有者：用自然语言说清要做什么、期望的最终状态是什么、边界在哪里，然后委派一个 worker；
- **worker** 是事实与执行所有者：探知对象类型、权限、冲突；用 LSP 和搜索确认引用；执行操作并修复引用；最后验证。

通过 SubAgent 隔离可缓解上级 Agent 为修复引用维护上下文产生的工具调用放大与智能区占用；仅当平台或上级 Agent 缺乏 SubAgent 能力时，上级 Agent 充当 Worker.

worker 支持五种语义明确的操作：**rename、move、merge、replace、delete**。它们互不替代——请求 move 而实际是 merge 时，worker 会停下来打回，等上级 Agent 明确意图后再继续。

引用不只指代码 import，还包括 Markdown 链接、配置文件、CI 脚本、符号链接、Git submodule 等。文本匹配只是候选，worker 必须先确认它指的确实是这个对象，才会动手修改。

## 示例：目标已存在时，打回而不是猜测

你说：

> 把 `src/legacy-api/` 移动到 `src/api/`

普通工具直接执行 `mv src/legacy-api src/api`，实际得到 `src/api/legacy-api/`——和你说的路径不符。

worker 的处理：

1. 探知：`src/api/` 已存在；
2. 判断：请求的语义是 move，但实际结果会是嵌套或合并；
3. 打回报告：
   - 请求：move `src/legacy-api/` → `src/api/`
   - 实际：嵌套为 `src/api/legacy-api/`，或与现有 `src/api/` 合并
   - 选项：A. 移动为 `src/api/legacy-api/`；B. 合并两棵目录树
4. 上级 Agent 明确意图后继续，并修复全部受影响的引用。

## 安装：交给你的 Agent

不同 Agent 框架的 skill 目录不同，把下面这句话发给你的 Agent：

`请把 filesystem-refactor 这个 skill 安装到[用户级|项目级]，文件在 <位置>`

## 使用方式

安装后，当你让 Agent 移动、重命名、合并、替换或删除文件/目录时，它会自行触发。也可以在请求中显式要求，例如"用 filesystem-refactor 把 docs 目录重组一下"。

构建、全量测试等高成本验证默认不执行；需要的话在请求里说明，比如"完成后构建受影响的包"。

## 它的边界

- **不承诺多文件原子性**：一次事务修改多个文件时，中途失败可能留下部分完成的现场；worker 会保存必要的恢复材料并尽力恢复，但不保证无损；
- **不免疫并发**：操作期间依然可能有其他进程同时改动同一批文件，结果以验证阶段的报告为准；
- **不保证保留所有平台特有元数据**：ACL、扩展属性等在部分平台上可能丢失；
- **效果上限取决于环境**：有 LSP 和 可用分析 MCP 时引用确认更准；支持子 Agent 时职责隔离更清晰。两者都没有时协议有降级路径，但置信度相应降低。

它的承诺是：探知过的才执行，语义不符就打回，改动过的都验证，验证结果如实报告。

## 设计取舍

给想改动这个 skill 的人：

- **单向需求流**：意图归上级 Agent，事实归 worker，worker 无权从讨论中推断"这算批准了"；
- **单写者**：一个事务只有一个 worker 写工作区，内容级合并由上级 Agent 出方案、worker 落盘；
- **打回优于猜测**：任何语义变化、未决碰撞、无处置方案的引用，都阻塞上报；
- **自然语言契约**：任务和报告都是给 LLM 看的自然语言，唯一的要求是每个对象的最终命运可唯一确定；
- **工具迁就语义**：选择工具的标准是它产生的具体结果与声明的意图一致。
