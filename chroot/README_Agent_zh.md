# chroot

`chroot` 是这个卷的语义根。它不是操作系统 chroot，也不暗示隔离。
该卷上一切有意拥有的内容都在此目录之下；Windows 在卷根创建的产物保留在它之外。

为一个条目找到归属时，首先要问的是：**谁拥有它、它扮演什么角色、它的生命周期是怎样的？**
每个目录要么是一个重定向锚点，要么是一个有明确操作语义的归宿。不存在纯分类性质的目录。

## 顶层契约

```text
chroot/
├── Control/        # 环境控制层：环境变量、脚本、配置文件、命令日志、需求记录（不装软件配置）
├── Software/       # 软件本体、配置、数据、缓存、包管理器、构建消费品
├── UserSpace/      # 用户的操作空间（Shell Folder 重定向 + 自主内容 + 凭证）
├── Projects/       # 你开发维护的项目
└── Archive/        # 暂离的材料，注意力管理工具
```

## `.pool` 与 `.META`

两个点号前缀标记目录，分工不同，通常不共存。**核心语义**：
`.pool` = "是我们的管理目标，上层有元数据"；不用 `.pool` = "不是我们的管理目标"。

### `.pool` -- 存储隔层

把一个用途分类的"管理语义"和"实际存储"分离：

```text
<用途分类>/
├── (管理语义所在，形式不约定)
└── .pool/               # 存储边界，在用途分类这层
    └── <具体工具>/       # 散装存储，无固定布局
```

- `.pool` 之上 = 管理语义所在，可被统一管理软件解析。具体形式不预先约定。
- `.pool` 之下 = 散装实际存储，不被解析。
- 统一管理软件只读 `.pool` 之上的语义，构建分类视图（如标签视图）。

**何时用**：是管理目标、且语义和存储需要分离时。如 rustup 接管的 Rust、Build2Use、Data、可重定向的应用缓存。
**何时不用**：不是管理目标时。
- 自洽官方软件单元（如 `python314`）--直接作为存储内容放在上层 `.pool` 之下，不在它内部再套 `.pool`。
- Windows 绑定文件夹（Shell Folders）--路径用 WinAPI 取，内部布局是 Windows 的，管不了。
- `Caches/Temp`--`%TEMP%` 重定向，我们只做重定向、不管内部。
- 源码项目--要被版本控制跟踪，用 `.META` 而非 `.pool`。

版本控制属性：`.pool` 同时是排除边界。原因：它不是源码，且可能有体积问题。不是因为可重建。
gitignore `**/.pool/`，rgignore 排除 `.pool`。

**结构化语义原则**：结构化语义永远在 `.pool` 之上，`.pool` 永远是叶子存储。

### 元数据管理

- 有 `.pool` 时元数据与 `.pool` 并列即可，不另建目录
- .META用于用户需要直接/或使用第三方软件打开这系列文件夹（而不是其中的某个文件）来查看、排布的场景，典型：
  - Projects 分类层，原因：对资产管理软件，IDE和用户查看视野友好
  - `Docs/`，原因：对用户友好，便于脚本编排成网站


资产单元的元数据（归属、标签、状态等），具体形式<尚未约定>
- 位置铁律：`.META`（和 `.pool`）永远贴着分类层，离资产至少一个目录的距离，绝不进资产单元内部
  资产单元内部（项目目录、软件目录）是它自己的世界，我们不碰
- 按需放，不强制每个分类层都有。


## 放置规则

1. 把软件放在其支持的安装模型允许的位置。开发工具进 `Software/Devtool/`，按用途分
   `envs`/`ide`/`agent`；应用软件进 `Software/Apps/`，按安装方式分 `Installed`/`Portable`。
2. 不要仅仅为了让目录树看起来纯粹而拆分厂商拥有的安装结构。当软件要求文件与程序同目录时，
   就让它们留在那里。appname 用安装器/解压设的名，原样保留，不另套厂商层。
3. 软件配置进 `Software/Configs/`（与 Data 并列），不进 Control。Control 只管环境控制层。
4. 凭证进 `UserSpace/Private/`，由 KeePass/1Password 等专门软件管，不单独顶层、不混软件配置。
5. 你开发维护的源码进 `Projects/`；只构建来用、不维护的源码进 `Software/Build2Use/`。
6. 在脚本和记录中使用 `%CHROOT_ROOT%` 而非编码盘符。
7. 顶层名称是稳定 API。仅当没有现有的所有权和生命周期分类能表示内容时，才添加新的顶层目录。

## 命名

- 结构目录使用 ASCII 英文名称和 `PascalCase`。
- 在结构目录之下，保留官方厂商/产品名称或安装器/解压设的目录名。
- 用户控制的命名空间内（如 `Devtool` 内的 `envs`/`ide`/`agent`、`Projects` 内的分组、项目、脚本）
  可用小写/snake_case。

参见每个顶层目录的 `README_Agent_zh.md` 以了解其本地契约。`TREE_Agent_zh.md` 是简洁的参考树。
