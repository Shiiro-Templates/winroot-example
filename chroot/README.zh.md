# chroot

`chroot` 是这个卷的语义根。它不是一个操作系统 chroot，也不暗示隔离。
该卷上一切有意拥有的内容都在此目录之下；Windows 在卷根创建的产物保留在它之外。

为一个条目找到归属时，首先要问的是：**谁拥有它、它扮演什么角色、它的生命周期是怎样的？**
声明式设置在有条件时是有用的，但它不是这个布局的前提。

## `.pool` 的含义

`pool` 只有多个逻辑消费者共享同一物理存储时才合理。例子包括以哈希命名的
内容寻址存储，或被多个项目使用的包管理器的单一下载/存储后端。
这些都是实现层面的概念，不是"把实际文件放这里"的同义词。
因此，普通安装的应用和 SDK 不需要 `.pool` 包装层；它们所在的分类目录已经是
物理上的家了。

## 现实的 Windows 示例

```text
Software/Installed/Microsoft VS Code/       # 安装器管理的程序体
Software/Portable/Everything/               # 自包含的便携应用
Software/PackageManagers/Scoop/             # Scoop 拥有的根和布局
Software/Toolchains/Rust/                   # 手动放置的工具链

State/Apps/obsidian/                        # 路径可控的应用状态
Cache/Packages/cargo/                       # 可安全重新下载的包缓存
Home/Knowledge/personal-vault/              # 用户创作的知识库
Workspaces/Repositories/demo/               # 活跃的源码仓库
```

应用特定的兼容目录（如 `Roaming`）可以在其自身状态边界内存在，
但 `Local`、`LocalLow` 和 `Roaming` 是 Windows 的存储类别，
