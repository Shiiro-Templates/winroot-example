# 术语与概念映射

本文件记录 chroot 布局中容易混淆的术语与概念区分，供 Agent 参考。
README 不含这些讨论--README 是契约，不是会议纪要。

## 交付物 vs 缓存

区分按**消费关系**，不按可重建性。

- **交付物**：被直接消费的东西。即使可重建，它正在被使用，删除会破坏正在进行的消费关系。
- **缓存**：仅为避免重建/重新下载而保留、不被直接消费。删除只产生重建成本，不破坏消费关系。

判定：删除后是否有正在进行的消费关系被破坏？有 -> 交付物；无 -> 缓存。

反例：`target/` 完全可重建，但有自己的目录、不进统一缓存--它是正在被运行/测试的工作本体（交付物）。可重建 ≠ 缓存。

安全维度：误标交付物为缓存 = 雷霆清理删掉正在用的资产（不可逆，危险）；误标缓存为交付物 = 浪费空间（可接受）。安全优先于整洁。

由此推出："可重建 -> 缓存 -> 忽略"是三段谬误，每个环节独立决策，互不蕴含。

## Projects vs Build2Use

- **Projects**：你开发、维护的源码项目。代码被版本控制跟踪，用 `.META` 装元数据。
- **Build2Use**：你只构建来用、不维护的源码软件。源码+构建产物是大块非源码消费品，用 `.pool` 收纳。

判定：这份源码你是要改它、维护它，还是只 build 出来用？前者 -> Projects；后者 -> Build2Use。只使用、不维护的源码不应该放在 Projects。

## `.pool` 的版本控制属性

`.pool` 是版本控制排除边界。原因：它不是源码，且可能有体积问题。不是因为可重建。

- gitignore `**/.pool/`，rgignore 排除 `.pool`
- 装的不只是缓存：SDK 本体（交付物）也进 `.pool`，因为它大且非源码
- 反例：锁文件可重建，但是源码且小 -> 被跟踪，既不进 `.pool` 也不是缓存

`.pool` 与 `Caches` 是两个独立维度：`.pool` 是版本控制层面的排除（非源码 ∧ 大）；`Caches` 是消费关系层面的归类（仅为避免重建/重下 ∧ 不被直接消费）。多数缓存也该 `.pool`，但两者非同集合。
