# 欢迎回家

`winroot/`是一种面向开发者的目录、应用组织管理图式，旨在把你的 windows 目录有条理的统一编排，绕开 windows 的默认文件夹地狱

对于 Windows 而言，我们并没有直观的根目录，取而代之的是主文件夹与盘符。
主文件夹成了事实上的快速访问点，奈何其软件支持只能说是半斤八两；
更不幸的是，windows在盘符下总是乱塞东西，有些是无法移动的......

`winroot/`旨在为用户提供一个自主决定布局、不受其余软件干扰的目录树

## 支持与依赖

仅提供 Win10 1607 (build14393)以上 与 Win 11 23H2 以上的支持
本项目推荐使用 [pixi](https://pixi.sh)（一个快速的跨平台包管理器）执行脚本与管理临时环境变量，开发者使用 pixi 0.77+

## 快速开始

当前仅描述从 0 开始，迁移暂需自行琢磨
1. 将 winroot-example 移动到卷的根下，重命名为你喜欢的名字，如`/chroot`、`/winroot`
2. 将 Windows Shell Folders 重定向到 `UserSpace/` 下对应目录
   - 在文件资源管理器中右键"文档"/"图片"/"下载"等 → 属性 → 位置 → 移动到 `UserSpace/` 对应子目录
3. 在 `Control/MotivationIndex/` 记录你的第一个需求

Tips: 开启 windows 开发人员模式与长路径支持效果更佳；
在功能受支持的 Win11 版本中，你可以使用 Dev Drive 与 ReFS 获得更好的体验

## `winroot/` 的哲学

### 声明式、语义化

目录是一种命名空间
- `winroot/`采用自解释的命名方案，配合必要粒度的 README 以降低索引成本，提升深层目录的可达性
- `winroot`采用直观且细致的命名方案

### 面向需求

人类需求是发展之根，Agent系统之源；任何现状只是需求的一个满足方式

`winroot/`提倡记录软件、目录、文件的本来需求；这样，我们并不需要搬运目录和其中的程序，而是通过满足需求来重建工作区

### Agent Friendly

`winroot/` 将 LLMAgent 视作一种独立主体而不仅是用户的辅助者
- `_Agent` 是与 `_en-US`, `zh-CN` 一样的语种
- Agent 有独立的探索、理解、管理目录的方式，通过 `.META/AgentSkills` 描述

`winroot/`提供人机关系优化的 Agent 环境
- Human in the Loop
- 人类的任务是划定意图、边界并最终负责、Agent的任务是辅助用户的观测、清晰用户的判断、实现用户的意图

### 渐进发展

`winroot/`提倡通过决策记录留下发展历史，将需求与实现的变迁融入结构变迁之中，提炼发展中的变量与不变量，从而感悟出更好的模式

### 易清理

`winroot/`提倡记录变更痕迹，追溯软件安装与运行时副作用、痕迹，努力做到应用卸载时依用户意图撤销变更

## `winroot/`的边界

`winroot/`不能做到
- 纯函数声明式系统状态管理：windows及其软件含固有的不可控性
- 自动化追溯一切安装、操作、卸载及其副作用：侵入面较大且依然会被绕过
- 对内部文件的版本化管理：你应该使用git等独立软件进行管理
- 保证数据的安全与可恢复：你应该使用合理的访问控制与兜底设施
